    Do

    • Keep the emblem and both names on every page; link them to the home page.
    • Put at most two co-branding logos (flagship programmes) beside the search.
    • Use the same menu on every page.

    Don't

    • Open menus on hover only; they open on click or Enter so keyboard and touch users can reach them.
    • Add more than six or seven top-level items.

    Accessibility

    • The brand link's name is its visible text plus (home page) (WCAG 2.5.3).
    • Menu buttons report aria-expanded; Esc closes the open menu and returns focus.
    • The drawer is a native <dialog>: focus stays inside until it is closed.

    The full header, with language, colour theme and accessibility controls, is in the home page template.

    Accessibility

    • The current page is marked with aria-current="page" in the breadcrumb and the tabs, not by colour alone.
    • Section tabs are links between pages, so they are not ARIA tabs.

    Buttons

    One primary action per screen. Use <button> for actions and <a> for navigation; both take the same classes.

    All documents

    Do

    • Label buttons with what they do: "Submit application", not "OK".
    • Use --lg --block for the main action of a short form on phones.

    Don't

    • Put two primary buttons side by side.
    • Use a link styled as a button to submit a form.

    Accessibility

    • Icon-only buttons need an aria-label.
    • Set aria-busy="true" while saving; the label stays for screen readers.
    • Focus shows a 2px outline in every state.

    Form fields

    Each field is a .ds-field with a visible label, an optional hint and the control. Mark required fields with required and a red asterisk, and tell users at the top of the form what the asterisk means.

    We never ask for the full number.

    Enter an email address in the correct format, like name@example.gov.in

    +91

    Do

    • Write errors that say how to fix the problem: "Enter a 10-digit mobile number".
    • Use the right type, inputmode and autocomplete.
    • Size short inputs to their content with .ds-input--w4, --w10, --w20.

    Don't

    • Use placeholder text instead of a label.
    • Disable paste in password or email fields.

    Accessibility

    • Errors are linked with aria-describedby and marked aria-invalid="true".
    • Inputs have a 3:1 border and a visible focus ring (WCAG 1.4.11, 2.4.7).

    Accessibility

    • A captcha must have a non-visual alternative (WCAG 1.1.1, GIGW 3.0). Offer a text question, such as "What is seven plus four?", generated on the server.
    • State accepted formats and the size limit before upload; the selected file name is announced.

    Validation and error summary

    Add data-ds-validate novalidate to a form. On submit, the script checks the browser's built-in rules, writes each error next to its field and shows a summary at the top with links to the fields. Errors clear as soon as a field is corrected. Always validate again on the server.

    Accessibility

    • Use role="alert" only for errors that need attention now; role="status" for confirmations.
    • Toasts stay while the pointer or focus is on them, and are announced politely.
    • Never put the only copy of important information in a toast.

    Dialogs

    A native <dialog>: open it with data-ds-open="id" or MotaDS.openDialog('id'). Focus moves inside, Esc closes it, and focus returns to the button that opened it. Links to other websites show a dialog like this when the page has <body data-ds-external-notice>.

    Accessibility panel

    Text size and display options from the header (GIGW 3.0). Each button carries data-ds-a11y; the script applies the option to the whole page and remembers it. Options: font-down, font-reset, font-up, contrast, invert, saturation, links, hide-images, cursor, spacing, reset.

    Application shell

    For dashboards, back offices and admin panels: a sidebar that collapses to an icon rail (and becomes a drawer on phones), a top bar with search, notifications and the user menu, and a content area of .ds-panels arranged in 12-column .ds-rows. A button with data-ds-app-toggle collapses the sidebar; the choice is remembered.

    See the complete markup in the dashboard template, and the sign-in screen in the sign-in template.
