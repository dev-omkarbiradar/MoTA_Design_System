    Accessibility and GIGW 3.0

    How the design system meets the Government of India web guidelines, and what each application still has to do.

    Standards

    The system is built to the Guidelines for Indian Government Websites and Apps (GIGW 3.0), the Digital Brand Identity Manual (DBIM v3.0) and WCAG 2.1 level AA (also the basis of IS 17802). Every template passes an automated axe-core scan with no WCAG 2.1 A or AA violations.

    Components do not make an application compliant by themselves

    Content, images, documents and the application's own code must also comply. Before launch, test with a screen reader (NVDA or JAWS on Windows, TalkBack on Android) and with the keyboard only, and get the STQC / CERT-In empanelled audit GIGW requires.

    Writing for everyone

    • Use short sentences and everyday words. Explain terms such as "PVTG" or "UC" the first time they appear.
    • Write link text that makes sense on its own: "Download the guidelines (PDF, 1.8 MB)", never "click here".
    • Give every image an alt that says what it shows; use alt="" for decoration.
    • Write error messages that say how to fix the problem.
    • Publish documents as accessible PDFs (tagged, with real text, not scans) or as HTML.
    • Write dates as "7 October 2026" and use Indian number grouping (₹1,24,503).

    Testing your application

    1. Keyboard: unplug the mouse. Reach every control with Tab, use it with Enter or Space, and close menus with Esc. Focus must always be visible.
    2. Zoom: zoom the browser to 200% and to a 320px-wide window. Nothing may be cut off or need sideways scrolling.
    3. Screen reader: with NVDA, list the headings (H) and landmarks (D), and fill in a form, including its errors.
    4. Automated scan: run axe DevTools or Lighthouse on every template of the application; fix every violation.
    5. Themes: select each colour theme and the high-contrast mode; everything must stay readable.
